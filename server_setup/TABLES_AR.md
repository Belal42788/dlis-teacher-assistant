# جداول السيرفر وعلاقاتها

| الجدول | فيه إيه | مربوط بإيه |
|---|---|---|
| `profiles` | كل حساب (مدير/مدرس/ولي أمر) ودوره | `id` = حساب Supabase |
| `classes` | الفصول | — |
| `students` | الطلاب (كود، اسم، فصل) | `class_id` ← classes |
| `activation_codes` | كود تفعيل لكل طالب (يخدم ولي أمرين) | `student_code` ← students |
| `parent_students` | أي ولي أمر مربوط بأي طالب | `user_id` ← profiles، `student_code` ← students |
| `grades` | درجات الطالب لكل أسبوع وبند | `student_code`، و`teacher_id` المدرس صاحبها |
| `publications` | تقارير/ملفات مشاركة لأولياء الأمور | `class_id` أو `student_code`، و`teacher_id` |
| `week_plans` | خطة الأسبوع (واجب/مواد/اختبارات) | المفتاح: فصل + ترم + أسبوع + **مادة** |
| `announcements` | الإعلانات (بتاريخ بداية ونهاية) | بالجمهور (الكل/مدرسين/أولياء) |

## القواعد
- **المدير** يعدّل كل حاجة. **المدرس** يعدّل بس درجاته ومنشوراته وخطط مادته. **ولي الأمر** يقرأ بس بيانات ابنه.
- جدول الطلاب للمدير بس (المدرس يقرأ ولا يعدّل).
- لو مدرسين اتنين دخلوا خطة نفس الأسبوع لمادتين مختلفتين: كل واحدة محفوظة لوحدها (قبل كده كانت بتمسح التانية).
- الكود الواحد يتفعّل لحد ولي أمرين، وولي الأمر نفسه لو كتبه تاني مفيش مشكلة.
- اتضافت فهارس (indexes) عشان السرعة لما الطلاب يكترو.

بعد أي تعديل في `schema.sql`: افتح **SQL Editor** في Supabase، الصق الملف كله، واضغط Run. آمن تعيده.
