# جداول السيرفر وعلاقاتها

| الجدول | فيه إيه | مربوط بإيه |
|---|---|---|
| `profiles` | كل حساب (مدير/مدرس/ولي أمر/طالب) ودوره | `id` = حساب Supabase |
| `classes` | الفصول | — |
| `students` | الطلاب (كود، اسم، فصل) | `class_id` ← classes |
| `activation_codes` | كود تفعيل لكل طالب: كود لأولياء الأمور (يخدم ولي أمرين) وكود تاني لحساب الطالب نفسه (مرة واحدة، من الصف الأول) | `student_code` ← students |
| `claim_attempts` | عدّاد محاولات الكود الغلط لكل حساب. بعد 20 محاولة غلط الحساب بيتقفل، والإدارة بتفتحه (`update claim_attempts set wrong = 0 where user_id = ...`) | `user_id` ← auth.users |
| `parent_students` | أي ولي أمر مربوط بأي طالب | `user_id` ← profiles، `student_code` ← students |
| `student_accounts` | حساب الطالب نفسه (من الصف الأول)، حساب واحد لكل طالب | `user_id` ← حسابات Supabase، `student_code` ← students |
| `teacher_classes` | المدرس بيدرّس أنهي فصول (فصل ومادة واسم المدرس بس، من غير أسماء طلبة)، البرنامج بيبعتها لما المدرس يسجل دخول | `teacher_id`، `class_id` |
| `threads` | محادثة بين مدرس وولي أمر طالب، أو بين مدرس والطالب نفسه (محادثة واحدة لكل مدرس وطالب ونوع) | `teacher_id`، `student_code` |
| `messages` | رسائل المحادثة (نص بس، 1000 حرف، مفيش تعديل، وعليها `sender_role` و`sender_name`) والمدير يقدر يخفي رسالة | `thread_id` ← threads |
| `thread_reads` | آخر مرة كل شخص قرأ المحادثة (عشان عدّاد غير المقروء) | `thread_id`، `user_id` |
| `message_reports` | بلاغات على رسايل، المدير يراجعها | `message_id` ← messages |
| `grades` | درجات الطالب لكل أسبوع وبند | `student_code`، و`teacher_id` المدرس صاحبها |
| `publications` | تقارير/ملفات مشاركة لأولياء الأمور | `class_id` أو `student_code`، و`teacher_id` |
| `week_plans` | خطة الأسبوع (واجب/مواد/اختبارات) | المفتاح: فصل + ترم + أسبوع + **مادة** |
| `announcements` | الإعلانات (بتاريخ بداية ونهاية) | بالجمهور (الكل/مدرسين/أولياء) |

## القواعد
- **المدير** يشوف ويعدّل كل حاجة. **المدرس** يشوف ويعدّل بس درجاته ومنشوراته وخطط مادته (مش بيشوف بتاعة مدرس تاني). **ولي الأمر** يقرأ بس بيانات ابنه، والملفات بعد ما تتوافق عليها وفي وقت ظهورها بس.
- جدول الطلاب للمدير بس (المدرس يقرأ ولا يعدّل).
- **المحادثات:** ولي الأمر يكلم بس مدرسين فصل ابنه، والطالب (من الصف الأول) يكلم بس مدرسينه، والطلبة ما بيكلموش بعض. ولي الأمر **يشوف** محادثات ابنه مع المدرسين (قراءة بس). المدير يشوف أي محادثة. مفيش حد يعدّل رسالة، ولا يمسحها. المدير بس يخفيها. أي حد في المحادثة يقدر يبلّغ عن رسالة.
- حساب الطالب بيشوف **نفس بالظبط** اللي بيشوفه ولي الأمر: درجاته، الملفات والخطط، الإعلانات، ومحادثات ولي الأمر مع المدرسين (قراءة بس) ومحادثاته هو. الكتابة بس في محادثاته هو.
- كل رسالة عليها صفة اللي كتبها (مدرس / ولي أمر / طالب / إدارة) بتتحط من السيرفر ومحدش يقدر يغيّرها. محادثة «ولي أمر الطالب» واحدة بتجمع الأب والأم مع بعض.
- اتجرّب كل ده على قاعدة بيانات Postgres حقيقية في الاختبارات (`tests/test_rls.py`).
- لو مدرسين اتنين دخلوا خطة نفس الأسبوع لمادتين مختلفتين: كل واحدة محفوظة لوحدها (قبل كده كانت بتمسح التانية).
- الكود الواحد يتفعّل لحد ولي أمرين، وولي الأمر نفسه لو كتبه تاني مفيش مشكلة.
- اتضافت فهارس (indexes) عشان السرعة لما الطلاب يكترو.

بعد أي تعديل في `schema.sql`: افتح **SQL Editor** في Supabase، الصق الملف كله، واضغط Run. آمن تعيده.
