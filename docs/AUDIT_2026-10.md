# Audit notes (October 2026)

Measured with 42 rooms, 1,260 students, 2,000 lesson-log entries, 300 tasks:
every read API < 4 ms, writes < 45 ms (grading sheet), boot ≈ 0.4 s, 36 requests / 445 KB on first load, 10 MB JS heap, idle = a ping every ~10 s and a reminders check every 20 s.

Fixed in this round
- Damaged JSON (bad syntax or wrong shape): restored from the newest good backup, the damaged copy is kept in `_backup/_damaged`, the teacher sees a notice. Never silently starts from empty.
- A busy file (OneDrive / antivirus / Word): reads and writes retry instead of failing or being treated as damage.
- Data folder unreachable at start: a clear screen instead of the first-run wizard.
- Word files: control characters / odd values in pasted or AI text no longer crash document creation.
- Requests with strange values return 400 instead of 500; half-sent requests time out after 60 s.
- One change to the data at a time (write lock; slow AI calls stay outside it).
- Launcher single-instance loop could spin the CPU if its socket broke.
- `open_file` only opens documents/folders, never programs.
- AI: dropped connections and school-firewall certificates handled (system certificate store fallback); rate limit on one model tries the next model.
- Static files use ETag (304) instead of no-store; Today page refreshes after midnight.

Known limits / suggestions
- A backup is the version *before* the last save, so a repaired file can miss the very last edit.
- Windows path length (260) can bite in a very deep OneDrive folder.
- Unsigned .exe triggers SmartScreen; a code-signing certificate fixes it.
